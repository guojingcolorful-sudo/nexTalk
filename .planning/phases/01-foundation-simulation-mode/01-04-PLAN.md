<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN WS peer → H5 | Frames cross from the LAN (token-gated but not TLS-authenticated) into the phone's render path |
| H5 → LAN WS | The phone's control/resume messages enter the desktop's SessionState |
| H5 render path | Decoded frames are committed to DOM state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02 | Tampering | WS inbound → H5 render | mitigate | isServerEvent field-validation narrowing on EVERY inbound frame before state (useWs); 64KB frame cap at the server (01-02); dedupe by seq; malformed payloads dropped (e2e section 5) |
| T-01-08 | Spoofing | LAN peer impersonating the desktop server | accept | LAN demo scope, token-gated client, no TLS (documented in RESEARCH Security Domain); the H5 holds the same session token — a rogue server would need LAN access + token; accepted for Phase 1 |
| T-01-10 | Denial of service | Reconnect storm / WS flood | mitigate | backoff ladder capped at 30s (no tight loops); server-side frame cap; no unbounded reconnect attempts |
| T-01-12 | Spoofing (XSS) | Rendered strategy/subtitle text | mitigate | React text nodes only — zero dangerouslySetInnerHTML / innerHTML in the H5; copy strings static; strategy text rendered as escaped text (e2e malformed-frame check) |
| T-01-13 | Information disclosure | H5 served over plain HTTP on LAN | accept | Locked decision (CONTEXT.md D-04 demo scope); tokens are single-session and rotated per launch (01-02) |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | All installs pre-approved in 01-01 Task 1 blocking-human checkpoint; no new packages in this plan (reuses ws devDep, fontsource, FA 6.7.2, qrcode) |
</threat_model>
