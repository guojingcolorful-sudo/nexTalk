<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust event bus → webview renderers | Events from SessionState (potentially fed by untrusted WS clients' control messages) cross into React |
| Console webview → Tauri command surface | The console window can invoke start_session and read pairing info |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02 | Tampering | 'session' events → bubble/timeline render | mitigate | useTauriEvents narrows every payload through isServerEvent before state updates (Task 1 hook, consumed in Tasks 1-2); malformed payloads dropped, never rendered (ChatBubble test 3) |
| T-01-04 | Information disclosure | QR + pairing URL in console | accept | QR only in the console window (never dual); stealth is Phase 4; demo scope documented in RESEARCH Security Domain |
| T-01-07 | Denial of service | Command surface (start_session spam) | accept | Single-user local app; session state machine ignores start when already running (01-05 wiring); ASVS L1 does not require rate limiting for local IPC |
| T-01-06 | Elevation of privilege | Console → dual window API | mitigate | capabilities/default.json limits window operations to allow-show on dual and allow-minimize/close on console (verify in this plan's review of the 01-02 capabilities file) |
</threat_model>
