## 1. System Classification

**System Type:** Realtime streaming voice pipeline（级联式 STT→增量翻译→克隆 TTS，非 RAG / 非 Agent / 非 Content Generation）

**Description:**
NexTalk 的实时语音翻译链：用户以中文说话，系统经云端 STT 识别、增量翻译为英文、以用户克隆音色合成输出，端到端 ≤2s（含冷启动）；同时面试官英文经第二路 STT 供双语字幕与 AI 辅助。使用者是跨国技术面试中的求职者。"好"的定义：面试官听到无缝、自然、无数字错误、术语准确、无抢话无重叠的英文；用户全程看到可读、不打断、可追溯的字幕。

**Critical Failure Modes（绝对不能发生的 5 件事）:**
1. **看起来流畅但语义错误的英文被说出口**（数字/术语/否定词错译——"流利的错误"比"明显的翻译失败"危害大百倍）
2. 端到端延迟越过 2s 预算导致抢话/重叠（用户已说下一句，上一句英文才播放）
3. STT 不稳定 partial 被当成 final 说出（半句话被播出，无法收回）
4. 供应商故障导致输出完全静默或卡死（用户对着面试官失语）
5. 成本失控（月度账单爆炸，产品不可持续）

## 1b. Domain Context

**Industry Vertical:** 求职面试辅助（职业发展 / 语言服务交叉）

**User Population:** 中文母语、目标为英语跨国技术面试的求职者；每用户单次面试 45-60 分钟，每月 2-8 次

**Stakes Level:** **High** — 面试结果直接影响录用；错误译文可能造成资历误述或冒犯

**Output Consequence:** 译文直接以声音呈现给面试官（不可撤回）；字幕呈现给用户本人

### What Domain Experts Evaluate Against

| Dimension | Good（面试官接受） | Bad（面试官察觉/反感） | Stakes | Source |
|-----------|-------------------|----------------------|--------|--------|
| 自然度 | 语调自然、无机器腔、无中断感 | 每句都有明显停顿、合成腔重、抢话 | 面试官注意力被技术干扰 | 用户系统论文档 + 延迟预算 |
| 术语准确性 | 专业术语（如 "slow query log"）与简历一致 | 术语硬译/错译（如把「连表查询」译成 join query 之外的怪译） | 技术能力误判 | 用户设计文档（RAG 强制检索原则） |
| 数字一致性 | 「800 毫秒」↔ "800 ms" 全链路一致 | 数字、数量级被 STT/翻译改掉 | 资历与成果误述 | D-04 确定性校验 |
| 可信表达 | 无把握时用户能感知（低置信标记），不会误信 | 错误译文无任何警示，用户照读 | 面试翻车 | 用户设计文档（弃权原则） |
| 连续性 | 全程无静默断档 | 供应商故障导致失语数秒 | 面试节奏崩坏 | D-09..D-12 容错链路 |

### Known Failure Modes in This Domain

- **抢话（barge-in）**：前句未播完，用户已说下一句 → 输出重叠（02-03 barge-in 队列）
- **数字漂移**：中文「一百二十万」与英文 "1.2 million" 单位/数量级错位
- **术语缺位**：领域黑话无术语库支撑，LLM 自由发挥（Phase 4 术语库，Phase 2 先埋 termHits 数据）
- **环境噪音**：面试官侧键盘声/回声污染 STT（AEC3 回声消除，02-05）
- **供应商抖动**：跨国网络 RTT 波动导致预算瞬时爆表（实验 RTT 实测先行）

### Regulatory / Compliance Context

- 无行业监管（非医疗/法律/金融）。隐私义务：语音数据出境至云 API，需最小化暴露 + 录制告知同意（PROJECT.md 已记录；分轨录制合规在 Phase 6）。
- 个人信息保护：克隆音色属敏感生物特征数据——克隆样本与音频不落自有云端（纯本地，v1 无后端）。

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|---------------|
| 用户本人（中文母语、真实面试场景使用者） | 盲听测试判定（音色相似度/自然度）、真实面试演练验收 |
| 双语技术面试老手（如有） | 术语准确性与语域校准、评测集标注 |
| Claude（研究/规划代理） | 自动化延迟/一致性/容错评测集构建与校准 |

## 2. Framework Decision

**Selected Framework:** **无重型框架——直连供应商 WSS/流式 HTTP（tokio-tungstenite + reqwest）+ 自研类型化阶段契约**（沿用 Phase 1 的 Rust 管线）

**Version:** tokio-tungstenite（latest）、reqwest（latest）——与 Phase 1 LAN 服务器同栈，无新增框架依赖。

**Rationale:**
- 2s 预算下管线必须级联流式（禁止整句串行），所有供应商接口都是 WebSocket 或流式 HTTP——直连客户端是唯一零缓冲路径；任何"框架"（LangChain 类编排层、SDK 整句封装）都会引入整句缓冲或额外序列化开销。
- Phase 1 已验证的技术栈即 Rust + tokio：音频图、状态机、LAN 服务器同运行时，零跨语言边界。
- 供应商锁定风险由**类型化阶段契约**（每阶段 trait：SttSource / Translator / TtsSink，镜像 Phase 1 SimSource 抽象）消化——换供应商只换实现。
- CLAUDE.md 已排除 Rust `webrtc` crate（巨大复杂）与本地模型（预算不达标）。

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Rust `webrtc` crate | 为 OpenAI Realtime 准备，WebRTC 栈复杂度远超需求；WSS 已够 |
| LangChain / 编排框架 | Python 生态 + 整句批处理假设，与 2s 级联流式冲突 |
| 供应商官方高级 SDK（整句模式） | 隐藏流式细节，缓冲语义不可控 |
| 本地模型（whisper.cpp 等） | 老 Mac CPU 预算不达标（决策已锁定，全云端） |

**Vendor Lock-In Accepted:** Partial — 每阶段单供应商但接口抽象隔离；备用供应商 v1 与否实验后定（D-11）。

```bash
# silero-vad-rs（问句结束检测）
```

### Core Imports
```rust
// 阶段契约（本阶段新建，镜像 SimSource 抽象）：
// trait SttSource { async fn stream(&mut self, pcm16: &[i16]) -> Stream<Item = SttPartial>; }
// trait Translator { async fn translate(&mut self, zh: &str) -> Stream<Item = EnFragment>; }
// trait TtsSink   { async fn synth(&mut self, en: &str) -> Stream<Item = AudioChunk>; }
```

### Entry Point Pattern
```rust
// 级联流式主循环（禁止整句串行——所有 stage 同时运行）：
tokio::join!(
    mic_loop(stt_tx),            // cpal 采集 → 重采样 → VAD 分段
    stt_loop(stt_rx, tr_tx),     // STT partial/final → 翻译触发
    translate_loop(tr_rx, tts_tx),
    tts_loop(tts_rx, out_tx),    // 克隆 TTS → 播放
    watchdog_loop(/* 延迟瀑布 + 熔断状态机 */)
);
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| 阶段契约 trait | 每阶段接口抽象（供应商无关） | 换供应商只换实现；实验 A/B 即插即拔 |
| partial/final 语义 | STT 中间结果 vs 定稿（Phase 1 PITFALLS 预告） | 只有 final 可触发 TTS（D-16 不变量） |
| 熔断状态机 | 每供应商 CircuitBreaker（closed/open/half-open） | D-10：2 次失败熔断 120s |
| 延迟瀑布 | 每阶段边界注入时间戳 | 02-01 测量装置，e2e 归因 |

### Common Pitfalls
1. 把 STT partial 当 final 播出——半句话无法收回（D-16 不变量）
2. 整句串行等翻译——必破 2s 预算；必须片段级级联
3. 忘了 44.1k↔48k↔16k 重采样边界——每个供应商边界都要过 rubato
4. Gemini Live 音频格式固定 PCM 16-bit/16kHz mono 100ms 块——边界契约写死
5. macOS 12.7 上老 SDK 链接警告（10.12 vs 12.0）——部署目标对齐

### Recommended Project Structure
```
apps/desktop/src-tauri/src/
├── audio/            # cpal 采集/播放、rubato 重采样、AEC3/VAD 预处理器
├── pipeline/
│   ├── stages/       # stt_source.rs / translator.rs / tts_sink.rs（trait + 供应商实现）
│   ├── cascade.rs    # 级联主循环 + 片段队列
│   ├── breaker.rs    # 熔断状态机
│   └── budget.rs     # 延迟预算 + 成本计量
├── trace/            # JSONL 事件流落地（D-05..D-08）
└── lan/state.rs      # 既有：事件广播（新字段 confidence/trace/abstained）
```

## 4. Implementation Guidance

**Model Configuration:**
- STT 中文（用户路径）：Gemini Live 文本模态 / Deepgram Nova-3 / 讯飞流式听写——实验定
- STT 英文（面试官路径）：Deepgram Nova-3 / 讯飞——实验定
- 翻译：Gemini Flash-Lite 或 DeepSeek-chat，temperature 0（翻译确定性），max_tokens 按片段（单句）
- TTS：火山复刻 ICL 2.0（已定，D-11：盲听 MOS 5.0/5.0，国内直连，1.3s 合成；备用供应商 v1 可免，失败走降级显示原文）
- **全链路温度 0、无创意采样、无思维链**（R1 类推理模型在实时翻译禁用——延迟陷阱）

**Core Pattern:**
片段级级联：STT final 片段（3-5 词即触发）→ 翻译流式片段 → TTS 流式合成 → 播放。三阶段同时运行（join!），共享有界队列（背压），绝不整句串行。

**Tool Use:** 无 agent 工具。术语注入（未来 Phase 4）走提示词内的 glossary 块；Phase 2 只记录 termHits 占位。

**State Management:**
内存 timeline（Phase 1 SessionState 沿用）+ JSONL 事件流落盘（D-05 追加写）。会话级 epoch（Phase 1 已建）。

**Context Window Strategy:**
翻译上下文 = 当前片段 + 前一句译文（滑窗 ≤2 句），禁止全文累积——2s 预算与 token 成本双约束。简历/术语库上下文属 Phase 5（策略卡），不在本阶段管线内。

## 4b. AI Systems Best Practices

> 本系统为 Rust 直连管线，无 Python/Pydantic——以 serde 类型化契约替代（同职能）。

### Structured Outputs with serde（替代 Pydantic）

```rust
// 翻译阶段的结构化输出契约——拒绝自由文本外的任何漂移
#[derive(Debug, Serialize, Deserialize)]
#[serde(tag = "t", rename_all = "snake_case", deny_unknown_fields)]
pub enum TranslatorOutput {
    Fragment { text: String, final_flag: bool },
    Abstained { reason: AbstainReason },   // D-03：无声弃权
    LowConfidence { text: String, score: f32 }, // D-02：低置信标记
}
// 解析失败/字段违规 → 按 D-09 片段级重试，而非宽容降级
```

### Async-First Design
全部 tokio async；级联三阶段 join! 并发 + 有界 channel 背压；TTS 播放为唯一时序锚点。常见错误：在 async 循环里同步阻塞（cpal 回调内做网络调用）——回调只入队。

### Prompt Engineering Discipline
翻译提示词固定三段：系统指令（忠实翻译、保留数字与术语、无解释）→ 术语块（占位，Phase 4 注入）→ 待译片段。温度 0。禁止 few-shot 膨胀（每 token 都是延迟）。

### Context Window Management
滑窗 ≤2 句（当前 + 前句）——实时翻译无长上下文需求；超长句按 VAD/标点切分。摘要/压缩机制 N/A。

### Cost and Latency Budget
每面试小时边际成本预算 **≤ $3.5**（自算：STT ~$0.22 + 翻译 pennies + TTS $0.5-3）。延迟预算：STT 首发 ≤500ms、翻译 TTFT ≤500ms、TTS 首音 ≤800ms、总 e2e ≤2s 冷启动。缓存策略：语义缓存 N/A（口语不重复）；片段级路由固定（D-14）。

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|--------------------------|---------------------|----------|
| 端到端延迟 | e2e ≤2s 冷启动（P95），分阶段瀑布每段 ≤ 预算 | 延迟装置（02-01）自动化 | Critical |
| 中文 STT 准确度 | WER 目标（实验定基线），数字/术语子集 100% 抽查 | 评测集自动化 | Critical |
| 翻译保真度 | 数字一致性 100%（D-04 规则校验）、术语命中率、无幻觉插入 | 规则校验 + LLM judge 校准 | Critical |
| 稳定性不变量 | 「spoken English ⊆ committed finals」零违反（D-16） | 集成测试（模拟断流/重连） | Critical |
| 克隆音色相似度 | 盲听 MOS ≥ 3.5/5 + 相似度评级 | 人工盲听（实验框架 blind-clone-test-set） | High |

### Reference Dataset

**Size:** 20 例起步（4 场景 × 5 句）：技术术语密集（数据库/分布式）、数字密集（性能指标/用户量）、口语化短句（思考停顿/重复）、背景噪音模拟。

**Composition:** 每例含：中文原声（或 TTS 合成替身）、期望译文、必须保留的数字/术语清单、难度分级。

**Labeling:** 用户本人审校关键数字/术语；Claude 代理生成初版并校准；盲听子集（克隆音色）由用户判定。

### Metric Definitions（计算口径）

> 口径细节与治理文档 GOV 3.8 一致（2026-09-30 增补）。e2e 取 P95（连续 10 句超线告警）；WER = 错字数 ÷ 总字数（数字/术语子集逐字抽查 100%）；数字一致性 = 规则校验（不一致回退原文）；策略卡置信 = 意图判断置信 × 证据覆盖度 × 引用校验通过率（权重与红线实验标定）；差异信号：实体重叠率（Jaccard）、结构对齐（相似度算子，Phase 5 定）、风格指纹（句长/连接词/直接性特征距离）、时机差（卡生成时刻 − 开口时刻）；计量口径：STT 按分钟 / 翻译按 token / TTS 按字符；采样：三类异常全量保留，正常事件每会话首尾各 5 句。

### 失败案例库 + 回归评测（D-20）

**案例结构：** 每个失败案例 = 输入（音频片段/原文）+ 错误输出 + 期望输出 + **根因分类**（术语缺失 / 模型幻觉 / 音频质量 / 数字漂移 / 其他）+ 来源（低置信事件 / 用户反馈 / 人工抽检）。

**入库源（自动）：** JSONL 溯源流（D-05）中三类事件自动成为候选案例：低置信标记、abstained 弃权、数字一致性校验失败（D-04）。候选经根因标注后转正入库。

**回归评测机制：**
- 每次修复与发布前，全量案例库回归：正确案例必须继续通过；失败案例在修复时转正为回归测试——「每一只逃出来的 bug 都要变成笼子上的新栅栏」。
- CI 集成：`pnpm -r test && pnpm exec playwright test && cargo test --workspace` + 回归套件（案例库 runner），全绿才可发布。
- 案例库随错误发现自动增长；Phase 4 术语库与 Phase 6 复盘从同一案例库消费。

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| 输出前确定性校验（D-04） | 数字/单位/日期在译文中与原文不一致 | Block 该片段 → 回退原文 |
| partial/final 不变量（D-16） | 非 final 片段到达 TTS 阶段 | Block（丢弃，等 final） |
| 低置信标记（D-02 修订） | 策略卡置信低于红线（Phase 5；翻译链不标置信） | Flag（策略卡角红章，实时被动标记） |

| 熔断降级（D-09..D-12） | 供应商连续 2 次失败 | Block 该供应商 120s → 降级「翻译服务暂时不可用」+ 原文 +「正在重试」 |
| 预算提示（D-15） | 月度用量接近阈值 | Flag（提示，不硬停——待与收费模式联动细化） |

## 7. Production Monitoring

**Tracing Tool:** 本地 JSONL 溯源事件流（D-05）+ 桌面成本面板（D-13）。无外部 SaaS 遥测（纯本地决策）。
