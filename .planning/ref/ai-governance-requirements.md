# AI 输出治理需求文档（NexTalk）

> 需求来源：用户 2026-09-29 两轮系统设计论述（系统论要素-连接-功能框架；三层容错架构）+ 失败案例库与回归评测补充。
> 本文档是 AI 输出治理的**需求口径**——用户视角的期望与验收标准；实现决策见 `02-CONTEXT.md`（D-01..D-20）与 `02-AI-SPEC.md`。
> 需求编号 GOV-xx 供跨阶段追溯；与 REQUIREMENTS.md 的 UI-/SYNC-/AUDI- 体系并行。

## 0. 背景与目标

NexTalk 的实时语音翻译链以云端 LLM 为内核。LLM 输出具有内在不确定性；产品的竞争力不在于模型多强，而在于**系统设计是否让 AI 输出可控、可溯源、可观测、可兜底、成本可算**——用系统论的方法，把 LLM 的不确定性关进工程化的笼子里。

系统论映射（用户手绘框架的工程落位）：

| 系统论层级 | NexTalk 模块 | 治理原则 |
|-----------|-------------|---------|
| 外部输入 | 音频流、多语言、设备、网络 | 鲁棒性（输入质量不稳定时的兜底） |
| 要素 | ASR 转写、LLM 翻译、术语库、用户上下文 | 可控（置信与弃权） |
| 连接 | 管线：音频→转写→翻译→输出 | 可兜底（重试/熔断/降级） |
| 输出与反馈 | 译文展示、低置信标记、错误反馈 | 可观测 + 可溯源 |
| 循环/闭环 | 失败案例库 → 修复 → 回归评测 | 越用越准，而非每次从零开始 |

## 1. 总原则

1. **可控**：rag检索简历库及术语库，配合网络检索，llm理解来给出回答框架，不可胡编。
2. **可溯源**：每一句译文都能追溯到音频时间戳、术语库来源、模型与版本。
3. **可观测**：每个模块的状态、置信度、成本都有埋点；观测是控制的前提，看不见就管不住。
4. **可兜底**：用户永远不会看到卡死或空白，系统不会因单点故障雪崩。
5. **成本可算**：先归因（哪一阶段在烧钱），再限额，最后优化。
6. **反馈闭环**：每一只逃出来的 bug 都要变成笼子上的新栅栏（失败案例库 → 回归评测）。

## 2. 三层容错架构

| 层 | 负责 | 落位 |
|----|------|------|
| 前端层 | UX 兜底：输入校验（麦克风权限/网络）、状态展示（正在转写/翻译/失败）、低置信标记、重试按钮、本地缓存 | 手机 H5 / 桌面 Webview（Phase 1 已建基础，Phase 2 扩展状态与标记） |
| 网关层 | 请求路由、重试、熔断、降级、成本闸门、模型切换 | **桌面 Rust 内核**（Phase 2 落地 D-09..D-15）；远程网关（服务器持 key）随商业化引入（Phase 8） |
| 管理后台 | 观测、配置、复盘、人工干预：成本看板、错误日志、卡点分析、模型切换开关、配额管理、人工确认 | Phase 8（公测前） |

卡点三分类：前端卡点（权限/网络/输入质量→提示+重试）；后端卡点（超时/限流/模型故障/成本超限→重试/熔断/降级/拒绝）；管理后台卡点（发现哪个环节失败率高、哪个用户烧钱多、哪个模型差→观测与配置）。

## 3. 需求明细

### 3.1 可控

- **GOV-01 策略卡置信三因子（2026-09-30 修订）**：作为用户，我希望系统对 AI 辅助策略卡的把握程度被量化，以便我知道何时该怀疑。验收：策略卡置信 = 意图判断置信 × 证据覆盖度 × 引用校验通过率三因子加权；阈值与权重经实验数据标定。阶段：Phase 5。翻译链不做置信标记（仅无声弃权与数字校验）。
- **GOV-02 低置信标记（2026-09-30 修订）**：作为用户，我希望低置信的策略卡有明显红色标记，而中置信不在直播中打扰我。验收：仅低置信策略卡角红色「低置信」微章（实时被动标记，零交互，不拦不响）；中置信黄色提醒只在复盘报告。阶段：Phase 5（实时标记）+ Phase 6（复盘黄标）。字幕不标置信（2026-09-30 修订）。
- **GOV-03 无声弃权**：作为用户，我希望音频无有效内容时系统诚实标记「待翻译」，而非硬编。验收：abstained 事件 + 「待翻译」标记；低置信不弃权（实时面试必须连续输出）。依据 D-03。阶段：Phase 2。
- **GOV-04 输出前确定性校验**：作为用户，我希望数字、单位、日期在译文中与原文严格一致。验收：数字/金额/日期一致性规则校验层覆盖全部译文，不一致即回退原文。依据 D-04。阶段：Phase 2。
- **GOV-05 翻译确定性配置**：作为用户，我希望翻译稳定可预期。验收：温度 0、无思维链模型（R1 类禁用）、上下文滑窗 ≤2 句。依据 AI-SPEC §4。阶段：Phase 2。

### 3.2 可溯源

- **GOV-06 逐句溯源落地**：作为用户，我希望每句译文可回溯。验收：JSONL 事件流逐句落盘（原文/译文/置信/时间戳/术语命中/供应商/模型版本）。依据 D-05/D-08。阶段：Phase 2。
- **GOV-07 语句级时间戳**：验收：每句记录相对会话起始的 ms 偏移。依据 D-06。阶段：Phase 2。
- **GOV-08 协议溯源字段**：作为用户，我希望手机上也能看到溯源信息。验收：线协议 subtitle 变体新增 confidence + trace（segmentStartMs/termHits/provider/modelVersion），新增 abstained 事件，向后兼容。依据 D-07。阶段：Phase 2。

### 3.3 可观测

- **GOV-09 分阶段成本计量**：作为开发者，我希望知道钱花在哪一阶段。验收：STT 按分钟、翻译按 token、TTS 按字符，逐句计量；**开发者管理后台展示完整分阶段信息**（Phase 2 本地开发面板 + Phase 8 云端管理后台）；**用户桌面设置页展示剩余分钟数**（本地累计用量，额度逻辑与分钟包月联动后细化）。依据 D-13。阶段：Phase 2（计量+双面板槽位）+ Phase 8（云端后台+分钟额度）。
- **GOV-10 埋点复用溯源**：验收：埋点日志复用 JSONL 溯源流聚合上报，不造第二套埋点；字段含用户/任务/模型/耗时/状态/错误码。依据 D-18。阶段：Phase 2 埋结构，Phase 8 上报。
- **GOV-11 管理后台看板**：作为运营，我希望公测前能看到成本看板、错误日志、卡点分析、模型切换开关、配额管理、人工干预入口。依据 D-17/D-19。阶段：Phase 8。

### 3.4 可兜底

- **GOV-12 片段级重试**：作为用户，我希望瞬时网络错误不打断对话。验收：超时/429/5xx 重试 2 次、指数退避 100→200ms、总预算 500ms 内放弃该片段并流下一片段；禁止整句串行重试。依据 D-09。阶段：Phase 2。
- **GOV-13 熔断**：验收：供应商连续 2 次失败熔断 120s，半开探测恢复。依据 D-10。阶段：Phase 2。
- **GOV-14 降级展示**：作为用户，我希望供应商故障时看到明确提示而非静默。验收：红色微章 +「翻译服务暂时不可用」+ 显示原文 + 副标注「正在重试」（文案中文锁定）。依据 D-12。阶段：Phase 2。
- **GOV-15 partial/final 不变量**：作为用户，我希望永远听不到半句话。验收：「spoken English ⊆ committed finals」零违反（仅 final 触发 TTS）。依据 AI-SPEC 关键失败模式。阶段：Phase 2。
- **GOV-16 备用供应商策略**：验收：A/B 实测双路径均达标且预算允许才配备用 key；否则单供应商 + 降级。依据 D-11。阶段：实验后定。

### 3.5 成本可算

- **GOV-17 预算提示**：作为用户，我希望用量接近阈值时收到提示。验收：月度用量阈值提示式（不硬停），与收费模式联动后细化；计量与展示职责见 GOV-09，本条只管阈值与提示。依据 D-15。阶段：Phase 2 提示 + Phase 8 联动定价。
- **GOV-18 固定路由**：验收：实验期每阶段单一供应商，自动升降级留到数据积累后。依据 D-14。阶段：Phase 2。

### 3.5b 可控（回答框架，Phase 5 承接）

- **GOV-23 回答框架 RAG（不可胡编）**：作为用户，我希望 AI 辅助给出的回答框架来自我的真实材料而非编造。验收：回答框架 = **简历库 + 术语库检索 + 网络检索**的证据 + LLM 理解组织；**每个策略点可追溯到简历条目/术语/检索结果（引用）**；无证据不出点（弃权）。依据 总原则 #1 扩展（2026-09-29 用户优化）。阶段：Phase 5（Phase 2 埋 termHits 数据结构为其地基）。
  - **防编造四层机制**（2026-09-29 增补，与设计原型四视图同步）：① **输入层·证据锁定**——简历条目 / 术语 / 检索结果逐条编号注入，上下文只放证据 + 当前问题（编造大多发生在「没东西写」时）；② **输出层·引用锁定**——每个要点必须带证据编号，代码校验编号真实存在、实体（公司 / 数字 / 技术栈）对得上，无引用即丢弃；③ **内容层·要点框架**——只出要点 + 参考措辞，不整段代写（与 ROADMAP Phase 5 成功标准 3 一致），短要点藏不住假信息——实时零交互（GOV-25），错卡无害，复盘再裁决；④ **兜底层·诚实降级 + 闭环**——检索失败回退本地简历 + 题库（唯一可验证来源），证据不足弃权，翻车进失败案例库「模型幻觉」根因专项、修复转正回归。引用 schema 字段、实体校验规则与幻觉注入评测集待 Phase 5 规划落定。
- **GOV-24 提问意图判断（可控）**：作为用户，我希望 AI 辅助的策略针对面试官真正想问的东西，而不是答非所问。阶段：Phase 5（承接 GOV-23 与 05-01 端点检测）。
  - **边界定义**：① 触发时机——只在提问结束后判断（双静默预算 550ms/1300ms + LLM 完整性判断；误触发 <5%、截断 <3%，ROADMAP Phase 5 成功标准 2）；② 判断形式——结构化分类，不做开放式长文分析：问题类型（行为题 / 技术深挖 / 简历追问 / 情景假设 / 施压反问）+ 目标实体（项目 / 技术栈）+ 期望形态（过程 / 结论 / 量化）+ 追问信号（是否延续上一轮主题）；③ 输入范围——当前问题 + 上一轮问答 + 简历锚点，禁止孤句判断（「那缓存层呢」依赖上文）；④ 生成约束——温度 0、单任务小判断叠加；⑤ 证据回验——检索命中与意图矛盾时取交集降级，以证据为准；⑥ 实时零交互——面试 / 会议中不能做任何操作（无弃用 / 标注）：错卡无害（要点框架 · 渐进渲染 · 与翻译链解耦）+ 系统自观（回答时自动比对，差异落盘）；裁决在复盘（GOV-25）。⑦ 检索策略——分类低置信时 top-2 意图并行检索、合并证据去重（2026-09-30 采纳）；⑧ prompt 骨架——三段式固定：系统指令 + 意图结构化标签 + 证据条目 + 当前问题，意图不以自然语言描述进入（2026-09-30 采纳）；⑨ 语域边界——v1 意图标签集只覆盖面试语域，会议 / 泛语域 v1 后按需扩展（2026-09-30 采纳）。
  - **测试判断**：① 意图分类准确率——回放语料标注（≥20 场真实面试回放），目标值 Phase 5 规划标定；② 检索联动——意图正确但检索为空记失败案例；③ 失败案例库根因分类新增「意图误判」（现有五分类无此项）；④ 与端点检测联合回归——misfire <5%、截断 <3%；⑤ 幻觉注入评测集——篡改或移除证据条目，验证模型不编造（2026-09-30 采纳）。
- **GOV-25 差异记录（反馈闭环）**：作为用户，我希望系统越用越懂我的答题思路，而不是把「和我不同」当错误修。阶段：Phase 5 埋点 + Phase 6 复盘对照。
  - **实时零交互**：策略卡纯被动投喂，实时无弃用 / 标注等任何操作；容错 = 错卡无害（要点框架 · 渐进式渲染 · 与翻译链解耦）。
  - **自动比对**：用户开口回答（用户轨 STT 转写完成该轮）后，系统自动比对预测（意图标签 + 策略卡要点 + 引用证据）与实际（用户回答转写）；差异信号规则可算：实体重叠率、结构对齐、风格指纹、时机差。只记录，不下结论。
  - **差异口径**：差异 ≠ 错误。四类原因：意图理解偏差（→ 意图分类器标定样本）、个人风格偏差（→ 个人风格画像，学习不修复——风格恰是产品价值）、证据缺失（→ 知识库补充信号）、时机偏差（→ 端点检测与生成预算调参）。
  - **复盘对照**：复盘报告（Phase 6）呈现「预测 vs 实际」对照 + 自动候选原因，用户在复盘时确认或修正。
  - **升级路径**：用户标注「这个判断有问题」→ 升级为失败案例（根因分类含「意图误判」），修复转正回归；未标注的差异仅作学习信号。与失败案例库是两套口径：差异 = 学习信号，错误 = 缺陷信号。个人风格画像为 v2 迭代方向（2026-09-30 采纳）：v1 只建差异记录与复盘对照，不做画像生成。

### 3.6 反馈闭环（失败案例库 + 回归评测）

- **GOV-19 失败案例库**：作为开发者，我希望每次错误都被记录并归因。验收：案例结构 = 输入 + 错误输出 + 期望输出 + 根因分类（术语缺失/模型幻觉/音频质量/数字漂移/其他）+ 来源（低置信事件/用户反馈/人工抽检）；JSONL 溯源流中低置信、弃权、数字校验失败三类事件自动成为候选；首个案例已入库（0001：SSE 解析截断丢数字）。依据 D-20。阶段：Phase 2 建库，持续积累。
- **GOV-20 回归评测**：作为开发者，我希望修复过的错误永不回归。验收：每次修复与发布前全量案例库回归（正确案例继续通过 + 失败案例转正为回归测试）；CI 集成（三套测试 + 案例库 runner）全绿才可发布。依据 D-20。阶段：Phase 2 机制 + 全阶段执行。

### 3.7 商业化（Phase 8 承接）

- **GOV-21 公测机制**：作为运营，我希望观察每个用户的使用漏斗。验收：免费公测 + 内测码 + 邮箱注册；账号 → 埋点 → 观测顺序建设。依据 D-17。阶段：Phase 8。
- **GOV-22 分钟包月制**：作为用户，我希望价格可预期。验收：月费含分钟数、超出买量；边际成本 ≤ $3.5/面试小时。依据定价讨论。阶段：Phase 8。

### 3.8 数据指标与计算口径（2026-09-30 增补）

| 类别 | 指标 | 计算口径 |
|---|---|---|
| 延迟 | e2e 全程延迟 | 麦克风入声 → 耳机出声，取 P95 ≤2s（含冷启动）；连续 10 句超线告警 |
| 延迟 | STT 首发 / 翻译 TTFT / TTS 首音 | 音频首块 → 首个 partial ≤500ms；请求 → 首 token ≤500ms；请求 → 首块音频 ≤800ms |
| 延迟 | 打断响应 | 用户再开口 → 输出停止 ~100ms |
| 质量 | 中文 STT 准确率 | WER 字错率 = 错字数 ÷ 总字数；数字 / 术语子集逐字抽查 100% |
| 质量 | 翻译保真 | 数字 / 单位 / 日期与原文严格一致（规则校验，不一致回退原文）；无幻觉插入 |
| 质量 | 稳定性不变量 | 「播报 ⊆ 定稿」违反次数 = 0（≠0 立即停用） |
| 质量 | 克隆音色 | 盲听 MOS 主观评分 1-5，≥3.5（实测 5.0） |
| 质量 | 端点检测 | 回放语料人工标注：误触发 <5%、截断 <3%（≥20 场回放） |
| 质量 | 意图分类准确率 | 回放语料标注的正确分类比例（目标值 Phase 5 标定） |
| 置信 | 策略卡置信 | 加权三因子：意图判断置信 × 证据覆盖度 × 引用校验通过率；证据覆盖度 = 检索证据对问题关键要素的支撑比例；引用校验通过率 = 通过实体校验的引用数 ÷ 总引用数（权重与红线实验标定） |
| 差异 | 实体重叠率 | Jaccard：预测证据实体 ∩ 用户实际提及实体 ÷ 并集 |
| 差异 | 结构对齐 / 风格指纹 / 时机差 | 框架 vs 实际结构相似度算子（Phase 5 定）；句长 / 连接词 / 直接性特征距离；卡生成时刻 − 开口时刻 |
| 成本 | 分阶段计量 / 边际成本 | STT 按分钟 · 翻译按 token · TTS 按字符，逐句记录；每面试小时 ≤$3.5 |
| 健康 | 熔断频次 / 采样 | 120s 窗口 >3 次 → 换供应商提示；三类异常全量保留，正常事件每会话首尾各 5 句 |
