一、 项目背景与目标 (Background & Objectives)
随着全球化远程工作与跨国贸易的普及，语言障碍成为外贸沟通和跨国企业技术面试的核心痛点。现有的翻译软件存在“延迟高、无真声情感、易被发现”等问题。
本项目旨在打造一款桌面+移动端协同的“超级沟通外挂”。通过底层音频接管、实时语音克隆、以及大模型辅助，让用户在使用母语（中文）交流时，能在不被察觉的情况下，向对方输出流利、地道、且带有个人真实音色的外语，并提供实时的基于个人背景的面试/沟通策略提示。
二、 核心应用场景 (Target Scenarios)
跨国技术面试：应对全英文面试，支持在 Zoom/Teams 全屏共享桌面（Show Code / PPT）的高压场景下隐蔽运行。
外贸商务谈判：WhatsApp、Google Meet 跨国语音/视频会议，实时理解客户需求并流畅应对。
多语种跨国团队例会：日常工作汇报与无障碍沟通。
三、 产品需求与功能模块 (Product Requirements & Features)
3.1 核心音频接管与转换引擎 (Audio Core)
虚拟麦克风/扬声器创建：免侵入式接管各类会议软件（Zoom, Teams, 腾讯会议等）的音频输入输出。
中转英 + 音色克隆：用户对麦克风讲中文 -> 实时识别翻译 -> 克隆用户音色生成英文 -> 注入虚拟麦克风发送给对方。
英听英 (原声透传)：截获对方英文音频用于AI分析，同时直接通过耳机播放原声，保证用户听感无延迟、无干扰。
3.2 跨端提词器与“防抓屏”机制 (Anti-Screen-Capture & Sync)
为了应对面试官要求“全屏共享 (Share Entire Screen)”的场景，系统采用主从跨端互联设计：
桌面端后台静默运行：提供全局快捷键（如 Cmd+Shift+H），一键隐藏/唤出桌面端UI面板。
手机网页端提词器：
桌面端生成局域网连接/二维码，手机扫码即可变成“智能提词器”与“遥控器”（无需下载App）。
手机端上半屏展示双语实时滚动字幕（对方讲话内容）。
手机端下半屏展示 AI 面试辅助提示卡片。
支持在手机端一键切换显示语言（全中文/全英文/双语）。
3.3 AI 实时面试/谈判辅助 (AI Copilot Engine)
个人知识库前置导入：支持导入个人简历 (PDF/Word)、高频面试题库、外贸产品话术本。
多路信息智能决策：
实时监听对方提问，并在提问结束时自动（或通过手机按钮手动）触发 AI 思考。
综合【简历真实经历】+【题库预设答案】+【实时网络搜索（针对最新技术/行业动态）】，生成回答策略。
流式提纲生成：以 Bullet Points（要点提纲）形式在手机端快速流式输出，方便用户扫视后立刻用中文开口组织语言。
3.4 会后数据资产留存与分析 (Analytics & Retention)
音视频分轨录制：本地或云端保存双向原始录音（我的声音 vs 对方的声音）。
全量文本导出：提供双语对话逐字稿导出。
智能摘要分析：会议结束后，一键生成面试复盘报告、外贸客户跟进待办 (Action Items)、客户情绪及关键关注点提取。
四、 业务工作流演示 (User Workflow Example)
【场景：全英文高阶技术面试】
准备：用户在电脑端导入《Java架构师简历.pdf》，打开工具，将电脑扬声器/麦克风设置为 "AI Virtual Audio"。手机扫码打开提词器页面，放在电脑屏幕旁。
隐藏：面试官要求共享桌面看代码，用户按下 Cmd+Shift+H 隐藏电脑端面板。
提问：面试官（英文）：“你在电商系统中如何处理高并发带来的数据库瓶颈？”
AI提示：系统在 1.5 秒内，结合简历内容，在手机屏幕打出中文要点：1. 读写分离；2. 引入Redis热点缓存；3. QPS提升300%。
回答：用户看着手机提词器，从容地对电脑说中文：“第一步，我们做了读写分离...”
输出：系统瞬间翻译，并用用户的全英文克隆音色播报给面试官。面试官听到的是无缝衔接、逻辑缜密的完美英文回答。
五、 技术选型与架构规划 (Technical Architecture)
系统架构分为四层：底层驱动层、桌面客户端、云端大模型管线、手机Web交互端。
5.1 底层音频驱动层 (Audio Driver Layer) - 最核心难点
Mac OS (需适配 12.7 Monterey 老版本):
技术路线：开发/深度定制基于 CoreAudio HAL (Hardware Abstraction Layer) 的虚拟音频插件。
开源依托：基于 BlackHole (C/C++) 进行二次封装。确保在老系统上的稳定性及低延迟缓冲区读写。
Windows OS:
使用 Windows Audio Session API (WASAPI) 或 VB-Audio 驱动。
5.2 桌面客户端层 (Desktop Application)
开发框架：Tauri + Rust (强烈推荐) 或 Electron + Node.js (C++ Addons)。
推荐 Tauri 理由：音频流在内存中的拷贝和处理对性能要求极高。Rust 的内存安全和极高的运行效率，能有效降低音频延迟，且打包体积极小，对 Mac 老系统更友好。
局域网服务：客户端内部运行一个轻量级的 WebSocket/HTTP Server，负责与手机端通信。
5.3 实时 AI 处理管线 (Streaming AI Pipeline)
必须采用全流式 (Streaming) 并发架构，端到端延迟需控制在 2秒 左右。
语音识别 (STT)：Deepgram API（目前业界极快，支持中英双语流式识别）。
意图识别与翻译 (LLM)：GPT-4o-mini（用于日常极速翻译和静音检测断句）。
智能体引擎 (Agent/Copilot)：
核心模型：GPT-4o 或 Claude 3.5 Sonnet (支持超长上下文 128k，直接通过 Context Stuffing 注入简历，无需外挂复杂向量库)。
网络搜索 API：Tavily API (专为 LLM 优化的低延迟搜索引擎 API)。
音色克隆与合成 (TTS)：ElevenLabs API（支持零样本声音克隆，通过 WebSocket 支持极低延迟的流式音频流输出，英文情感极其地道）。
5.4 手机跨端互联层 (Mobile Web Interface)
技术栈：HTML5 + React/Vue + WebSocket。
交互机制：通过 Server-Sent Events (SSE) 或 WebSocket 接收桌面端推送的双语字幕和 AI 提纲，实现“字一个个蹦出来”的打字机渲染效果，有效掩盖 LLM 的生成延迟。
5.5 后端服务与存储 (Backend & Storage) (按需建设)
如果产品要做成 SaaS 供多用户使用：
后端：Golang (高并发长连接处理优势)。
数据库：PostgreSQL (用户信息)、MongoDB (非结构化会议记录/复盘报告)、AWS S3 (双轨录音文件存储)。
六、 核心技术挑战与应对策略 (Risks & Mitigations)
端到端延迟 (End-to-End Latency)
挑战：传统的 说话->识别->翻译->合成 的串行时间会超过 4-5 秒，导致面试严重冷场。
应对：必须实现级联流式处理 (Cascaded Streaming)。STT 只要识别出 3-5 个单词，立刻触发 LLM 翻译，LLM 吐出前半句翻译，立刻触发 ElevenLabs 合成音频，不等整句话说完就开始播放。
Mac 12.7 虚拟音频驱动签名与安装
挑战：苹果系统对音频层权限要求极高，驱动安装容易失败。
应对：提供详细的引导向导（类似安装录屏软件时请求授权），要求企业级开发者账号 (Apple Developer Program) 进行 Notarization 签名验证。
多重回声与啸叫控制
挑战：麦克风同时录制自己说话和扬声器漏音。
应对：集成 WebRTC 框架中的 AEC (Acoustic Echo Cancellation) 回声消除模块进行软件层面的音频预处理。
